# FFI Interface Specification

This document specifies the C ABI interface that all rustbridge plugins must export.

## Overview

rustbridge plugins expose a standard C ABI interface that host languages call via FFI (Foreign Function Interface). This interface handles:

- Plugin lifecycle (initialization, shutdown)
- Request/response communication (JSON and binary transport)
- Logging callbacks
- State queries and configuration

## Required Exports

Every rustbridge plugin must export these symbols with C linkage:

| Symbol | Signature | Description |
|--------|-----------|-------------|
| `plugin_create` | `fn() -> *mut c_void` | Create a plugin instance |
| `plugin_init` | `fn(*mut c_void, *const u8, usize, LogCallback) -> FfiPluginHandle` | Initialize the plugin |
| `plugin_call` | `fn(FfiPluginHandle, *const c_char, *const u8, usize) -> FfiBuffer` | Make a synchronous request |
| `plugin_free_buffer` | `fn(*mut FfiBuffer)` | Free a response buffer |
| `plugin_shutdown` | `fn(FfiPluginHandle) -> bool` | Shutdown the plugin |

## Optional Exports

These symbols provide additional functionality:

| Symbol | Signature | Description |
|--------|-----------|-------------|
| `plugin_set_log_level` | `fn(FfiPluginHandle, u8)` | Set log level dynamically |
| `plugin_get_state` | `fn(FfiPluginHandle) -> u8` | Query lifecycle state |
| `plugin_get_rejected_count` | `fn(FfiPluginHandle) -> u64` | Get rejected request count |
| `plugin_call_raw` | `fn(FfiPluginHandle, u32, *const u8, usize) -> RbResponse` | Binary transport call |
| `rb_response_free` | `fn(*mut RbResponse)` | Free a binary response |
| `plugin_call_async` | `fn(FfiPluginHandle, *const c_char, *const u8, usize, u64) -> FfiBuffer` | Async request (future) |
| `plugin_cancel_async` | `fn(FfiPluginHandle, u64) -> bool` | Cancel async request (future) |

## Type Definitions

### FfiPluginHandle

```c
typedef void* FfiPluginHandle;
```

Opaque handle to a plugin instance. Obtained from `plugin_init`, used in all subsequent calls.

### FfiBuffer

```c
typedef struct {
    uint8_t* data;      // Pointer to response data
    size_t len;         // Length of data in bytes
    size_t capacity;    // Allocation capacity (for freeing)
    uint32_t error_code; // 0 = success, non-zero = error
} FfiBuffer;
```

Buffer for passing data across the FFI boundary. Follows "Rust allocates, host frees" pattern:

1. Rust creates and populates the buffer
2. Host copies data to managed heap
3. Host calls `plugin_free_buffer()` to release memory

### LogCallback

```c
typedef void (*LogCallback)(
    uint8_t level,        // Log level (0=trace, 1=debug, 2=info, 3=warn, 4=error)
    const char* target,   // Logger target (null-terminated)
    const char* message,  // Log message (null-terminated)
    size_t message_len    // Message length (excluding null terminator)
);
```

Callback function for receiving log messages from the plugin.

### RbResponse (Binary Transport)

```c
typedef struct {
    uint8_t* data;       // Pointer to response struct
    size_t len;          // Response size in bytes
    size_t capacity;     // Allocation capacity
    uint32_t error_code; // 0 = success, non-zero = error
} RbResponse;
```

Response buffer for binary transport. Must be freed with `rb_response_free()`.

### RbString (Borrowed)

```c
typedef struct {
    uint32_t len;        // Length in bytes (excluding null terminator)
    const uint8_t* data; // Pointer to null-terminated UTF-8 data
} RbString;
```

Borrowed string reference. Caller owns the memory; valid only during the FFI call.

### RbBytes (Borrowed)

```c
typedef struct {
    uint32_t len;        // Length in bytes
    const uint8_t* data; // Pointer to binary data
} RbBytes;
```

Borrowed byte array reference. Caller owns the memory; valid only during the FFI call.

## Function Specifications

### plugin_create

```c
void* plugin_create(void);
```

Creates a new plugin instance. This is typically generated by the `rustbridge_entry!` macro.

**Returns:** Pointer to the plugin instance, or `NULL` on failure.

**Notes:**
- The returned pointer must be passed to `plugin_init`
- Do not free this pointer directly; use `plugin_shutdown`

### plugin_init

```c
FfiPluginHandle plugin_init(
    void* plugin_ptr,           // From plugin_create
    const uint8_t* config_json, // JSON configuration (can be NULL)
    size_t config_len,          // Length of config_json
    LogCallback log_callback    // Optional log callback (can be NULL)
);
```

Initializes the plugin with configuration and starts its lifecycle.

**Parameters:**
- `plugin_ptr`: Plugin instance from `plugin_create`
- `config_json`: UTF-8 encoded JSON configuration, or `NULL` for defaults
- `config_len`: Length of `config_json` in bytes
- `log_callback`: Function to receive log messages, or `NULL`

**Returns:** Handle to the initialized plugin, or `NULL` on failure.

**Notes:**
- The log callback must remain valid for the plugin's lifetime
- After successful init, the plugin is in `Active` state
- Configuration format is documented in [ARCHITECTURE.md](./ARCHITECTURE.md)

### plugin_call

```c
FfiBuffer plugin_call(
    FfiPluginHandle handle,     // From plugin_init
    const char* type_tag,       // Message type (null-terminated)
    const uint8_t* request,     // Request payload
    size_t request_len          // Length of request
);
```

Makes a synchronous JSON request to the plugin.

**Parameters:**
- `handle`: Plugin handle from `plugin_init`
- `type_tag`: Null-terminated message type identifier (e.g., "echo", "math.add")
- `request`: JSON request payload
- `request_len`: Length of request in bytes

**Returns:** `FfiBuffer` containing the response.

**Response Format:**
- On success: `error_code = 0`, `data` contains JSON response
- On error: `error_code > 0`, `data` contains error message

**Notes:**
- The returned buffer must be freed with `plugin_free_buffer`
- Panics in plugin code are caught and returned as error code 11

### plugin_free_buffer

```c
void plugin_free_buffer(FfiBuffer* buffer);
```

Frees memory allocated by `plugin_call` or other buffer-returning functions.

**Parameters:**
- `buffer`: Pointer to the buffer to free

**Notes:**
- Must be called exactly once per buffer
- After calling, the buffer is invalid
- Safe to call with a null buffer pointer

### plugin_shutdown

```c
bool plugin_shutdown(FfiPluginHandle handle);
```

Gracefully shuts down the plugin.

**Parameters:**
- `handle`: Plugin handle from `plugin_init`

**Returns:** `true` if shutdown succeeded, `false` on error.

**Notes:**
- Blocks until shutdown completes or times out
- After shutdown, the handle is invalid
- Timeout is configurable via `shutdown_timeout_ms` in config

### plugin_set_log_level

```c
void plugin_set_log_level(FfiPluginHandle handle, uint8_t level);
```

Dynamically changes the plugin's log level.

**Parameters:**
- `handle`: Plugin handle
- `level`: New log level (0=trace, 1=debug, 2=info, 3=warn, 4=error, 5=off)

### plugin_get_state

```c
uint8_t plugin_get_state(FfiPluginHandle handle);
```

Queries the plugin's current lifecycle state.

**Returns:** State code:
- 0 = Installed
- 1 = Starting
- 2 = Active
- 3 = Stopping
- 4 = Stopped
- 5 = Failed

### plugin_get_rejected_count

```c
uint64_t plugin_get_rejected_count(FfiPluginHandle handle);
```

Gets the number of requests rejected due to concurrency limits.

**Returns:** Count of rejected requests since initialization.

### plugin_call_raw

```c
RbResponse plugin_call_raw(
    FfiPluginHandle handle,     // Plugin handle
    uint32_t message_id,        // Binary message identifier
    const uint8_t* request,     // Request struct bytes
    size_t request_len          // Size of request struct
);
```

Makes a binary transport request using C structs instead of JSON.

**Parameters:**
- `handle`: Plugin handle
- `message_id`: Numeric identifier for the message type
- `request`: Pointer to the request struct
- `request_len`: Size of the request struct in bytes

**Returns:** `RbResponse` containing the response struct.

**Notes:**
- Response must be freed with `rb_response_free`
- Binary handlers must be registered via `register_binary_handler`
- See [TRANSPORT.md](./TRANSPORT.md) for binary transport details

## Error Codes

All error codes are stable across versions:

| Code | Name | Description |
|------|------|-------------|
| 0 | Success | Operation completed successfully |
| 1 | InvalidState | Invalid lifecycle state transition |
| 2 | InitializationFailed | Plugin failed to start |
| 3 | ShutdownFailed | Shutdown did not complete cleanly |
| 4 | ConfigError | Invalid configuration |
| 5 | SerializationError | JSON encoding/decoding failed |
| 6 | UnknownMessageType | Unrecognized type_tag |
| 7 | HandlerError | Handler returned an error |
| 8 | RuntimeError | Async runtime error |
| 9 | Cancelled | Operation was cancelled |
| 10 | Timeout | Operation timed out |
| 11 | Internal | Panic or internal error |
| 12 | FfiError | FFI layer error |
| 13 | TooManyRequests | Concurrency limit exceeded |

## Safety Requirements

All FFI functions have safety requirements that callers must uphold:

1. **Handle validity**: Handles must come from `plugin_init` and not be used after `plugin_shutdown`
2. **Pointer validity**: All pointers must be valid for the specified length
3. **String encoding**: All strings must be valid UTF-8
4. **Null termination**: `type_tag` must be null-terminated
5. **Single free**: Buffers must be freed exactly once
6. **Thread safety**: Calls to the same handle must not overlap (serialize calls or use appropriate synchronization)

## Generating FFI Exports

For Rust plugins, use the `rustbridge_entry!` macro:

```rust
use rustbridge_ffi::plugin_entry;

struct MyPlugin;
impl Plugin for MyPlugin { /* ... */ }

// Generate plugin_create
plugin_entry!(MyPlugin::default);

// Re-export FFI functions
pub use rustbridge_ffi::{
    plugin_init,
    plugin_call,
    plugin_free_buffer,
    plugin_shutdown,
    plugin_set_log_level,
    plugin_get_state,
    plugin_get_rejected_count,
};
```
